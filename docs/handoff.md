For a teammate or reviewer running AEGIS on another machine. Everything listed
as passed below was executed on the project machine (Windows 11, Docker
Desktop 29.8.0, 16 cores, 7.6 GB Docker VM). Nothing is estimated.

## 1. What AEGIS is

A real-time disaster intelligence and risk analytics platform (Big Data and
Modern Databases final package): synthetic weather, river-level, traffic and
citizen-report streams → **Kafka** → **Spark** (RDD, Spark SQL, Structured
Streaming, MLlib) → **HBase** + partitioned **Parquet** → **FastAPI** →
**React/Leaflet** dashboard. The default data is synthetic (`data/`). A
separate **real historical mode** (`data_real/`) runs the batch pipeline on
verified public data for 2023-11-01 – 2023-12-30 (ERA5, IMD, NOAA gauge,
DFO, GDACS) — see §3a. The two are never mixed.

* Dataset audit and migration (sources, evidence, mapping, ML audit, results): [dataset_audit.md](dataset_audit.md) · [dataset_migration_plan.md](dataset_migration_plan.md)

* Overview, stack and versions: [README.md](../README.md)

* Data dictionary: [data_dictionary.md](data_dictionary.md) · API: [api.md](api.md) · ML: [ml_model.md](ml_model.md)
* Tests: [testing.md](testing.md) · Faculty demo script: [demo_guide.md](demo_guide.md) · Requirement evidence: [traceability.md](traceability.md)

## 2. Setup on a new machine (Windows, PowerShell)

Prerequisites: Docker Desktop (WSL 2) running with **≥ 8 GB memory** and its
disk image on a drive with **≥ 10 GB free**; Node.js 18+; Git; Python 3.11
(optional, for host tools).

```powershell
git clone https://github.com/VishwajithGS/AEGIS.git
cd AEGIS
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -HostVenv   # builds aegis-spark + aegis-hbase, installs dashboard, creates .venv
```

First build downloads ~2 GB (base images, PySpark, HBase, Maven jars, npm). On a
slow link see [docker/spark/wheels/README.md](../docker/spark/wheels/README.md).

Not in the repository (recreated by setup or the generator): `.venv/`,
`frontend/node_modules/`, all of `data/` except `data/sample/`.

## 3a. Real historical data mode

Needs only the Spark image (step 1) and internet for the import; Kafka and
HBase are not used.

| # | Command | Purpose |
|---|---|---|
| R1 | `scripts\ingest_real_data.ps1` | download + validate + normalise ERA5, IMD, GHCN-D, DFO, GDACS → `data_real\raw\historical\` (cached; re-run is offline) |
| R2 | `scripts\run_real_data.ps1` | batch ETL in real mode, real-data gold tables, validation report, API container `api-real` on :8001 |
| R3 | `scripts\start_frontend.ps1 -RealData` (separate terminal) | dashboard :5174 against :8001 |
| R4 | `.\.venv\Scripts\python.exe scripts\ui_check.py --real --url http://127.0.0.1:5174 --out data_real/reports/ui` | browser check |

Where things are: adapters in `aegis/realdata/`, real-data Spark layers in
`spark_jobs/real_data_layers.py`, API in `backend/app/services/dataset_service.py`
and `analytics_service.real_data`, UI in `frontend/src/components/RealDataPanels.jsx`.
Real mode is selected only by environment overrides
(`AEGIS__STORAGE__DATA_ROOT=data_real`, `AEGIS__RISK__REPORTS_OBSERVED=false`,
`AEGIS__HBASE__ENABLED=false`, `AEGIS_API_LIVE_FEED=0`, `AEGIS_API_MODEL=0`);
the synthetic defaults in `config/aegis.yaml` are unchanged.

### 3b. Hybrid mode (real rainfall + synthetic fill)

`scripts\run_hybrid_data.ps1` (after R1) builds `data_hybrid\`: the real files
from `data_real\` plus synthetic water level, traffic, reports and incidents
generated by `producers/hybrid_generator.py` from the real ERA5 rainfall, then
runs the ETL, real-data layers, MLlib training and zone predictions, and
starts `api-hybrid` on :8002. Dashboard: `scripts\start_frontend.ps1 -Hybrid`
→ :5175. The script pauses `streaming`/`producers` during the batch jobs and
restarts them. Every synthetic record is tagged
`data_source = aegis-simulator-era5-driven`; see
[dataset_migration_plan.md](dataset_migration_plan.md) §5b for the results and
the 24 h wetness setting.

Open decisions for the project owner (details in
[dataset_migration_plan.md](dataset_migration_plan.md) §6): GloFAS discharge
as a proxy water indicator, NDMA SACHET live warnings, a real-data ML
objective (IMD next-24 h rainfall category), Kafka replay of real history,
and free account registrations (NASA Earthdata, Google Earth Engine,
ReliefWeb, data.gov.in).

## 5. Issues found while running it (all fixed)

See the table "Problems found by running it, and fixed" in
[traceability.md](traceability.md): PyPI timeouts during the image build,
uncounted out-of-region citizen reports, live inference without incident data,
imputed "rainy" predictions for empty windows, a streaming JVM OOM kill, an
over-long graceful stop, inflated rate metrics, colliding live/hourly HBase
rows, HBase aborting after a long host pause, and restart exhaustion.

## 6. Known limitations

Synthetic mode uses simulated data; real mode is historical batch only, its
hourly rain is ERA5 reanalysis (2 cells for all 40 zones), the IMD day
attribution is assumed, and it has no real water level, traffic, reports or
severity labels; single-node deployment; at-least-once delivery;
watermark-late events do not update live windows; ~20 s streaming latency on
the Windows bind mount; ML "High" class recall 0.28; ~8 GB Docker memory needed
for the full stack plus batch jobs (with less, stop `streaming`/`producers`
while running batch jobs). HBase rows written before 2026-10-21 14:15 UTC on
the project machine use the old zone-risk key format and are ignored by the API
(a fresh machine does not have them).

## 7. Notes for development

* All tunables: `config/aegis.yaml`; overrides via `AEGIS__SECTION__KEY` (see `.env.example`).
* Spark collects timestamps in the driver's local time zone; code that turns
  Spark rows into JSON renders timestamps as UTC strings inside Spark
  (`hbase_sink.iso`). Keep that pattern.
* Native Windows Spark cannot write files without Hadoop `winutils`; run
  file-writing jobs in the container.
* `run_e2e.ps1` shares checkpoints with the `streaming` service; the script
  pauses and restores the live services itself.
